# Telegram-бот для текстовой переписки

Python 3.12, aiogram 3, aiohttp, PostgreSQL. Приложение: Render Free;
история и очередь: Neon Free; модель: `nvidia/nemotron-3-ultra-550b-a55b:free` через OpenRouter.
После развёртывания компьютер можно выключить. Работают личные текстовые чаты,
allowlist по user ID, `/start`, `/help`, `/new`. Вложения не поддерживаются.
Сообщения передаются OpenRouter и провайдеру модели; история хранится в Neon.

Не добавляйте карту, не пополняйте баланс, не включайте платные или пробные планы.

## Настройка с нуля

1. В официальном [BotFather](https://t.me/BotFather) выполните `/newbot`, задайте имя
   и username. Токен сохраните только в `BOT_TOKEN` в Render. При желании через
   `/setcommands` задайте команды `start`, `help`, `new`. Не вставляйте токен в URL.
2. Зарегистрируйтесь в [OpenRouter](https://openrouter.ai/), в Keys создайте ключ.
   Баланс не пополняйте. Ключ нужен для `LLM_API_KEY`. Проверьте условия обработки
   данных и настройки приватности: они могут ограничивать доступные бесплатные маршруты.
3. В [Neon](https://console.neon.tech/) выберите **Free**, создайте отдельный проект,
   по возможности во Frankfurt. Из Connect скопируйте PostgreSQL connection string
   целиком в `DATABASE_URL` в Render. Сохраните параметры TLS, включая `channel_binding`.
   Подходят direct и pooled-подключения; клиент проверяет сертификат сервера.
4. Загрузите код в свой GitHub-репозиторий без `.env` и `.venv`. Репозиторий может
   быть приватным. При подключении Render предоставьте доступ только к нему.
5. В [Render](https://dashboard.render.com/) выберите **New → Blueprint** и подключите
   репозиторий с `render.yaml`. Проверьте **Web Service / Free**, без отдельного worker
   и без базы Render. Заполните переменные ниже. `WEBHOOK_SECRET` создаётся Blueprint
   автоматически. Ключи вводите в Environment сервиса, не в чат и не в исходный код.
6. В `ALLOWED_USER_IDS` укажите только свой числовой ID. Если ID неизвестен, временно
   оставьте список пустым: доступ всем закрыт. После deploy отправьте боту `/start`:
   в отказе он покажет ваш ID без обращения к модели и истории. Внесите этот ID
   в Render и сохраните настройки с перезапуском.
7. При запуске приложение применяет миграции и устанавливает HTTPS webhook
   на `/telegram/webhook`. Домен берётся из `RENDER_EXTERNAL_URL`; отдельный домен не нужен.
   Webhook использует секрет, `max_connections=1`, `allowed_updates=["message"]`,
   `drop_pending_updates=False`. Не увеличивайте число соединений.
8. Дождитесь `service_ready` в логах. Откройте
   `https://<ваш-сервис>.onrender.com/healthz`: ожидается `{"ok":true}`.
   Отправьте `/start`, затем обычный вопрос. Содержательный ответ на вопрос
   подтверждает реальный вызов модели с вашим ключом; `/start` модель не вызывает.

При ручном создании Web Service выберите **Free**, Python и команды из `render.yaml`,
health check `/healthz`. Для `WEBHOOK_SECRET` сгенерируйте отдельное значение:
`python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`.
Это не токен BotFather. Приложение не выполняет платных обновлений тарифов.

## Настройки

`.env.example` содержит только пустые значения. Приложение читает окружение процесса,
а не загружает `.env` автоматически.

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен BotFather, секрет |
| `LLM_API_KEY` | Ключ OpenRouter, секрет |
| `DATABASE_URL` | Строка Neon, секрет |
| `DATABASE_URL_UNPOOLED` | Прямое подключение Neon для миграций, секрет; без него используется `DATABASE_URL` |
| `WEBHOOK_SECRET` | 32–256 букв, цифр, знаков `_`, `-` |
| `ALLOWED_USER_IDS` | Ваш ID; позднее несколько ID через запятую. Пусто = отказ всем |
| `WEBHOOK_BASE_URL` | Обычно не задаётся; используется `RENDER_EXTERNAL_URL` |
| `LLM_API_BASE` | По умолчанию `https://openrouter.ai/api/v1` |
| `LLM_MODEL` | По умолчанию `nvidia/nemotron-3-ultra-550b-a55b:free` |
| `LLM_FREE_ONLY` | Оставьте `true`; платные модели и другой API запрещены |

Необязательные значения по умолчанию: `WORKERS=2`, `MIN_REQUEST_INTERVAL=5` секунд,
`MAX_PENDING_PER_USER=3`, `MAX_PENDING_TOTAL=30`, `HISTORY_TURNS=12`,
`HISTORY_CHARS=24000`, `MAX_INPUT_CHARS=8000`, `MAX_OUTPUT_TOKENS=1024`,
`MAX_OUTPUT_CHARS=12000`, `MODEL_TIMEOUT=60` секунд. Пустые значения используют defaults.
`PORT` предоставляет Render; локально — 10000. Лимит символов истории не включает
фиксированное системное сообщение. Клиент использует Chat Completions. Для OpenRouter
дополнительный режим reasoning отключён, чтобы ограниченный бюджет выходных токенов
оставался для видимого ответа. Адрес API, модель и ключ вынесены в настройки для
последующей адаптации к DeepSeek. Эта платная
интеграция сейчас не активирована.

## Подключение существующего проекта Neon

Node.js нужен только для Neon CLI и `neon.ts`; приложение остаётся на Python.
Локальная привязка `.neon`, зависимости `node_modules` и секреты `.env.local`
исключены из Git. Пример подключения:

```sh
neon login
neon init -y --org-id <org-id> --project-id <project-id> \
  --branch production --services postgres --no-agent-setup
neon config plan
neon deploy
uv build
uv run --env-file .env.local python -m telegram_ai
```

Команда deploy настраивает PostgreSQL и выгружает переменные; Python-приложение
по-прежнему размещается на Render. Перед локальным запуском добавьте в окружение
остальные обязательные настройки бота. В Render перенесите `DATABASE_URL` и
`DATABASE_URL_UNPOOLED` в Environment: первый используется для рабочих запросов,
второй — для миграций. Не публикуйте их значения. Если Node.js не установлен,
для обычного запуска бота он не нужен: строки подключения можно взять в Neon Console.

## Хранение и восстановление

Webhook проверяет секрет и доступ до работы с историей и моделью. HTTP 200
возвращается после записи задания в PostgreSQL, при ошибке записи — 503.
Очередь обрабатывается в том же приложении, максимум двумя заданиями одновременно.
Ключ дедупликации — `(bot_id, update_id)`. Сообщения пользователя выполняются
последовательно; порядок также зависит от доставки Telegram.

Аренда задания действует 180 секунд и продлевается во время работы. После падения
процесса просроченное задание восстанавливается. Ответ сохраняется до отправки,
прогресс отправки частей фиксируется отдельно. Вызов модели — максимум две попытки
на задание, включая восстановление; 402/429 автоматически не повторяются.
Для каждой части ответа в Telegram — до четырёх попыток. Окончательный сбой доставки
отмечается как `failed` в БД и логах без содержимого сообщения.

`/new` удаляет текущую историю, очищает старые задания и отменяет их результаты.
Текущая отправка может задержать фиксацию `/new` до своего таймаута. Уже отправленные
сообщения не удаляются; запрос, ушедший провайдеру, не отзывается. Резервные копии Neon
и копии сообщений у внешних провайдеров `/new` не очищает. Команда отмены может обойти
лимит очереди, чтобы оставаться доступной.

Сохраняются только последние `HISTORY_TURNS` успешно доставленных пар. В модель
передаются последние целые пары в пределах `HISTORY_CHARS`. Ошибки в историю не входят.
Разметка отключена; части ответа ограничены 4000 единицами UTF-16. Тексты завершённых
заданий удаляются, идентификаторы дедупликации хранятся семь дней и очищаются при новых
updates. Отказ по частоте или очереди означает, что вопрос нужно отправить повторно.

Exactly-once для внешних API нет: падение между внешним вызовом и фиксацией в БД
может повторить генерацию или часть отправки. Если Render уснул, восстановление
ожидает следующего настоящего входящего запроса; задержка может превышать три минуты.
В простое база не опрашивается, чтобы Neon мог засыпать.

## Актуальные сведения

Для каждого запроса передаётся текущая дата по Москве. На прямые вопросы
«какой сейчас год» и «какая сегодня дата» приложение отвечает по серверным часам,
без обращения к модели или поисковику. В остальных случаях модель возвращает
обычный текст или вызывает `web_search` в режиме `tool_choice=auto`.
Поиск выполняется через DDGS (DuckDuckGo и Google, затем Yahoo/Bing/Brave при сбое), без
платных поисковых API и ключей. До трёх результатов и выдержки публичных страниц
передаются модели; в ответ добавляются ссылки. Поисковикам передаются поисковые
слова, а не вся история. Не отправляйте боту секреты и персональные данные.

Поисковики могут блокировать запросы, а сайты — требовать JavaScript или ограничивать
чтение. Поисковые выдержки могут быть неполными или устаревшими. При сбое поиска
бот сообщает, что свежие сведения не проверены. Для вопросов об актуальных фактах
возможны два обращения к бесплатной модели, поэтому квота расходуется быстрее.
Модель должна поддерживать вызов функций (`tools` и `tool_choice`). Встроенные
платные поисковые инструменты OpenRouter не используются.
На один ответ выполняется не больше одного поискового запроса; повторяющиеся
вызовы с тем же запросом используют его результат. Для остальных вызовов модель
получает явное сообщение, что дополнительный поиск не выполнен.

## Локальные проверки

Установите [uv](https://docs.astral.sh/uv/) и Docker. Тесты используют настоящую
PostgreSQL и **очищают таблицы**: разрешена только отдельная БД с именем на `_test`.
Если порт занят, выберите другой. Дождитесь готовности БД перед запуском pytest.

```sh
uv sync --locked
docker run --detach --rm --name telegram-ai-test-postgres \
  --network bridge -p 127.0.0.1:55432:5432 \
  -e POSTGRES_HOST_AUTH_METHOD=trust -e POSTGRES_DB=telegram_ai_test \
  --tmpfs /var/lib/postgresql/data:rw,size=256m postgres:17-alpine
docker exec telegram-ai-test-postgres pg_isready -U postgres -d telegram_ai_test
export TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:55432/telegram_ai_test
uv run pytest -q
uv run ruff check src tests
uv run ruff format --check src tests
docker stop telegram-ai-test-postgres
```

Trust-аутентификация здесь предназначена только для временной БД на loopback.
Telegram и модель в тестах заменены управляемыми ответами. Это не проверка аккаунтов.
Для локального запуска передайте настройки через окружение и выполните
`uv run python -m telegram_ai`; webhook требует публичного HTTPS-адреса.
Не запускайте локальную и облачную копии одновременно для одного бота.
При уже настроенном окружении доступны:

```sh
uv run python -m telegram_ai.manage check-model
uv run python -m telegram_ai.manage set-webhook
uv run python -m telegram_ai.manage webhook-info
```

`check-model` выполняет один реальный запрос и расходует квоту. Ключи передавайте
через окружение, не через аргументы команд. Shell Render Free не требуется:
миграции и webhook настраиваются приложением.

## Приёмка в облаке

Проверьте вопрос и уточнение с историей, `/help`, `/new` во время генерации,
отказ на вложение и отказ с постороннего аккаунта. Для двух намеренно разрешённых
аккаунтов проверьте разделение историй. Отправьте два вопроса с интервалом не меньше
пяти секунд и проверьте порядок. Перезапустите сервис и проверьте историю, отдельно —
восстановление задания после перезапуска во время генерации.

Не обращайтесь к сервису более 15 минут, затем задайте вопрос в Telegram и дождитесь
ответа. Во время ожидания не открывайте `/healthz` и не включайте внешний мониторинг,
который будит приложение. Только это проверяет реальное пробуждение webhook.
До выполнения этих шагов реальная переписка, доступ с ключом, работа Neon и Render
и восстановление после сна остаются непроверенными.
